Session 1 · CSS

Styling and layout

ConceptKey idea
Three ways to add CSSInline (on the tag), internal (<style>), external (<link> to a .css file). External is best: one file styles many pages.
SelectorsElement (p), class (.highlight), id (#title), descendant (.box p), pseudo-class (a:hover)
Specificityinline > #id > .class > element. Equal strength: the rule written last wins.
Box modelcontent + padding + border + margin. box-sizing: border-box makes width include padding and border (300px stays 300px, not 350px).
FlexboxStyle the parent, children move. justify-content (main axis), align-items (cross axis), flex-direction, gap.
Responsive designMobile-first default styles plus @media (min-width: 768px); the viewport meta tag is required for phones.
display & positiondisplay:none removes the box and its space; visibility:hidden keeps the space. relative shifts from its normal spot; absolute sticks to the nearest positioned parent.
Grid vs FlexboxFlexbox for one direction (navbars, button rows, cards). Grid for rows and columns (galleries, page layouts).
BootstrapReady-made CSS loaded from a CDN; class names such as btn btn-primary and col-md-4 do the styling.
/* Mobile first, then enhance for laptops */
.cards { display:flex; flex-direction:column; gap:10px; }
@media (min-width:768px) { .cards { flex-direction:row; } }
Spot the bug exercise. Four hidden mistakes: a <link> to a missing CSS file (404), an anchor #Projects that doesn’t match id="projects" (ids are case-sensitive), an image with no alt, and a label for="mail" that doesn’t match id="email".

Git ≠ GitHub. Git is the version-control tool on your computer and works offline. GitHub is a website that hosts copies of Git repositories.

The eight chapters

1

The problem

Ends the project_final_REAL habit: history, undo and collaboration. Git is distributed: every copy has the full history.

2

Three places

Working directory, index, repository. Most commands just copy data from one area to the next.

3

Inside .git

HEAD, config, index, objects/, refs/, logs/. Delete it and the history is gone.

4

Objects

Blob (file), tree (folder), commit (snapshot), tag. Names are SHA-1 hashes of content, so history can’t be changed quietly.

5

Branches & HEAD

A branch is just a tiny file holding a commit hash. Merges are fast-forward, three-way, or conflicted.

6

Undo

restore --staged and reset are safe; restore and clean destroy uncommitted work. Use git clean -nd first.

7

.gitignore

Ignore secrets, node_modules/ and logs. It can’t untrack a committed file: use git rm --cached.

8

Remotes

clone, push, fetch, pull (= fetch + merge). Only sharing needs a network.

Session 2 · Hands-on

The guided lab and commands

The lab has 15 steps plus 5 optional extras (look inside .git, hash by hand, real merge commit, resolve a conflict, undo safely). The core workflow:

git init                       # create the repository
git status                     # what changed?
git add .                      # stage everything
git commit -m "First commit"   # save a snapshot
git log --oneline              # read the history
git branch feature             # create a branch
git checkout feature           # switch to it (or: git switch)
git commit -am "Dark theme"    # commit on the branch
git checkout main
git merge feature              # bring the work into main
Merge outcomeWhen it happens
Fast-forwardmain has no new commits; the pointer just slides forward, no new commit.
Merge commitBoth branches have new work; Git creates a commit with two parents.
ConflictSame lines changed on both. Edit between <<<<<<< and >>>>>>>, then git add and git commit (or git merge --abort).
Simulator extras. “What just happened” explains each command, “Live repo” mirrors a real folder as you type in cmd, and Practice has a quick quiz with 10 exercises. Real push/pull aren’t simulated: they are covered in the steps for GitHub.

Wrap-up

Key takeaways

  1. HTML is the skeleton, CSS the skin, JavaScript the brain.
  2. Use semantic tags, matching label/id pairs and alt text: they affect accessibility and correctness.
  3. Write mobile-first CSS and add media queries; use Flexbox for one direction, Grid for two.
  4. A commit is a snapshot of the whole project, not a list of edits.
  5. Files travel working directory → staging → repository; commit small and often with clear messages.
  6. Branches are cheap, so experiment freely and merge when it works. A conflict is normal, not an error.
  7. Know which undo commands are safe, and never commit secrets: add .gitignore before the first git add ..
